# Ручной перевод с пульта

Решение 2026-10-10: отказаться от автоматического запуска по HDMI/приложениям
и определения языка. В меню Game Translator открыть кнопку «Перевод», нажать OK,
затем «Назад» к игре. Переключение одной глобальной кнопкой поверх HDMI не
реализовано: обычное фоновое приложение не получает keypress, rooted путь
требует проверки на самом ТВ.

`translationEnabled` в `/media/developer/game-translator-layers.json` — один
флаг текущего сеанса, default OFF. Версия 0.1.7 сбрасывает прежний ON при каждом
старте контроллера, после сна/выключения и при пробуждении ТВ. Оформление не
сбрасывается. Phone PIN API меняет тот же флаг и вызывает
немедленную инвалидизацию допуска при переключении. Контроллер опрашивает
состояние каждые 2 секунды; ручной ON начинает работать после возврата к игре.

`tv-power.js` использует постоянный локальный Luna subscriber по найденному в
AmbiSun URI. Нужны подтверждённая подписка и известное awake-состояние. Сон,
потеря подписки, неизвестное состояние и её ошибка сбрасывают OFF; возвращение
On/Active не восстанавливает ON. Кнопка ON из TV-меню/телефона отклоняется, если
бодрствование не подтверждено. UI опрашивает только TV-локальное состояние,
чтобы после пробуждения не показывать старый ON. Чёрный кадр игры не является
системным состоянием питания.
На границе питания инвалидируются подготовленные команды, включая ON при уже
выключенном флаге. Телефон не повторяет ON автоматически при 409/ошибке сети.
Revision нового процесса получает отдельный seed, чтобы прежняя команда не
совпала с новым экземпляром. После пробуждения требуется новый ручной ON.

Source ID по-прежнему нужен для блокировки позднего результата другого экрана,
но не для списков разрешений. Собственные меню/overlay не обрабатываются;
открытие настроек не меняет флаг. Флаг OFF запрещает новые frame jobs, а
принятый проход может завершиться; текущий pipeline пока ждёт переводов.
Новое правило OFF — прекращение рабочего обмена OSD с Orange, включая фоновые
автоопросы. На Orange отдельный supervisor выгружает тяжёлые модели/работники
через 300 секунд отсутствия активности, оставляя доступный endpoint пробуждения.
Принятый проход может завершиться; после OFF его ответ не отображается.
В версии 0.1.6 фоновые запросы настроек/бюджета Orange прекращаются на OFF.
TV/phone меню читают локальные snapshots и показывают время получения, либо
«расход неизвестен», если снимка ещё нет. Локальные запросы браузера к TV-меню
продолжаются, но на Orange не перенаправляются. Открытие TV-меню также не вызывает
автоматический GET settings на Orange; для явной операции есть кнопка обновления.
Ввод ключа/сохранение provider — явные действия пользователя, отдельно от polling.
Проверка ключа на телефоне требует PIN-session/Origin и отдельного явного POST.

Независимый OCR_DONE, supervisor и выгрузка ещё не реализованы. В целевом режиме
до истечения пяти минут повторный ON использует тёплые модели.

В Google-профиле предварительный Bergamot остаётся: Google отправляется после
его этапа и трёх совпадений исходного текста одной области в свежих кадрах.
Только окончательный Google-ответ попадает в Google cache. Одинаковые переводы
Bergamot/Google не вызывают повторную перерисовку OSD. Подключение этой цепочки
также ожидает отдельного этапа; текущий relay имеет фиксированный provider madlad.

Пакет: settings 0.1.7 и mobile-osd-controller-0.1.7.tar.gz. Установка прежняя:
`install-mobile.sh` после IPK, сохранить приватный provider config отдельно.
Capture/PicCap и Orange production не переключались. Host-тесты проверяют
manual OFF/ON, отсутствие запуска по спискам/языку и source invalidation.
ТВ недоступен: live установка и работа кнопки OK ещё не подтверждены.
Node-тесты считают реальные HTTP-вызовы proxy и доказывают ноль фоновых Orange
запросов на OFF, включая несколько клиентов меню. Python regression подтверждает,
что принятый OCR-ответ после OFF не передаётся OsdPublisher.
Новые тесты проверяют startup OFF, standby/wake без рестарта, потерю подписки,
таймаут, запрет включения во сне, JSON stream framing и завершение subscriber.
Сам tvpower API и поля ответов ещё не проверены на G5; неизвестный/неподтверждённый
ответ оставит новую версию в OFF до исправления по реальному evidence.
