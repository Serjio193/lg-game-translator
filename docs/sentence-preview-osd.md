# Завершённые предложения и OSD — 0.1.9

Предварительный Bergamot получает отдельные завершённые предложения. Границы
берутся из существующего `translator/sentences.py`: `.`, `!`, `?`, с исключениями
для сокращений, инициалов, десятичных чисел и многоточий. Модель OCR и её
параметры не меняются. В комплект ТВ тот же файл упакован как
`relay/sentence_boundaries.py`, без отдельной копии правил в исходниках.

`Follow me! Take` отправляет только `Follow me!`. Когда OCR получает
`Follow me! Take care!`, первая часть переиспользуется, переводится только
`Take care!`. Готовые части показываются по порядку, включая промежуточный
ответ, когда второе предложение ещё переводится. Текущая предварительная
строка восстанавливается из памяти сразу при дописывании исходного блока.

Кэш частей ограничен предложениями текущего кадра и текущей сессией. Он
не сохраняется в БД; одинаковые одновременные запросы используют общий Future.
Исправление исходного предложения требует нового перевода. Старый ответ не
публикуется с admission старого блока; актуальное общее предложение может
переиспользоваться. OFF проверяется перед каждым новым запросом и публикацией.

Незавершённый хвост не переводится на первых двух наблюдениях. Для описаний
и заголовков без пунктуации сохранена отправка после трёх совпадений. Это
существующий компромисс, **не доказательство завершения TYPEWRITER**. Рост/
длительность печати пока не анализируются. Финальный Google/MADLAD получает
целый текущий блок после трёх подтверждений, а не отдельные предложения.
Кэш целых блоков используется финальным endpoint; preview теперь проверяет
кэш по предложениям, поэтому готовый кэш многопредложного блока не исключает
предварительную работу Bergamot.

OSD получает `sentence_flow`: обычный перенос слева направо вместо балансировки
строк вокруг центра, верхний отступ 4 px OSD и расширение области только вправо.
При продолжающемся исходном блоке сохраняется левый верхний якорь первого
показанного перевода. При добавлении текста сначала пробуем текущий размер;
если не помещается, уменьшаем его. Изменения font-size/letter-spacing имеют
CSS transition 180 ms. Переносы строк пересчитываются сразу, они не анимированы.
Исходные координаты OCR, ручные настройки и правило чтения новых реплик сохранены.
Существующие translation-pairs/multi-subtitles/layout-height переиспользованы
из основного checkout: очередь принимает новые предварительные предложения и
продолжение исходника на том же DOM id без пятисекундного ожидания. Для другой
реплики очередь остаётся прежней. DOM узлы не отсоединяются на каждом обновлении;
иначе CSS-анимация теряет предыдущее отображённое состояние. Фильтр высоты
layout-height перенесён без изменения алгоритма.

Маска по-прежнему относится к целому OCR-блоку: на живом ТВ необходимо проверить,
не закрывает ли она ещё непереведённый хвост. Точных координат каждого предложения
в нынешнем контракте нет; пропорциональное угадывание координат не добавлялось.
При нехватке области остаётся существующий fallback субтитров внизу экрана.

Проверки: regression на границы, дописывание/исправление, переиспользование
первой части и late result, существующие admission/coordinator tests; Node
проверяет левый якорь, размер и сохранение transition при повторном OCR.
92 релевантных Python tests и 18 Node test files прошли. IPK и архив 0.1.9
собраны. ТВ доступен, но установленное меню 0.1.1 не содержит нового комплекта;
установка 0.1.9 пока не выполнена. Сборка пакета не доказывает плавность
анимации на ТВ; реальный TYPEWRITER и маска хвоста требуют живой проверки.
